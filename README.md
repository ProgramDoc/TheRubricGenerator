# TheRubricGenerator

**OGAI · LLM Evaluation & Rubric Generation Platform**  
Repository: [github.com/ProgramDoc/TheRubricGenerator](https://github.com/ProgramDoc/TheRubricGenerator)

---

## Overview

TheRubricGenerator is an AI-powered evaluation platform for assessing LLM performance on clinical research papers. It implements a **two-LLM pipeline**:

1. **Claude** generates a structured rubric (questions + ideal answers + scoring criteria) from a PDF
2. A **second LLM** (default: GPT-4o via OpenAI) answers the rubric questions
3. **Claude-as-judge** grades the second LLM's answers against the rubric
4. Results are displayed with per-question scores, reasoning, and CSV export

This implements the LLM-as-judge pattern with **human-in-the-loop validation** — the rubric can be edited before evaluation runs, avoiding the circularity problem of using the same model to generate and grade.

### Database schema (SQLite)
- `users` — session-based auth (PBKDF2-SHA256)
- `sessions` — 30-day session tokens
- `projects` — folder organization
- `papers` — uploaded PDFs
- `rubrics` — generated/edited rubrics (JSON)
- `evaluations` — evaluation runs + graded results

## Rubric Types

| Type | Description | Questions |
|------|-------------|-----------|
| `classification` | Study design & OGAI taxonomy | 8–12 |
| `extraction` | PICO/PICOS structured extraction | 10–15 |
| `risk_of_bias` | Bias domain appraisal | 10–14 |
| `custom` | User-defined via instructions | Variable |

## Evaluation Models

Any OpenAI or Anthropic model can be used as the evaluator:
- **GPT-4o** (default) — OpenAI's flagship multimodal model
- **GPT-4 Turbo** — previous generation
- **GPT-4o mini** — faster, cheaper
- **Claude Sonnet 4** — Anthropic (cross-model comparison)

Grading always uses Claude via the Anthropic API.

## Workflow

### Single paper
1. Upload PDF → sidebar
2. **Rubric tab**: select rubric type → Generate Rubric with Claude
3. Edit questions/scoring criteria as needed
4. **Evaluate tab**: select model → Run Evaluation
5. Click **Grade with Claude** for scoring
6. **Results tab**: view per-question scores + export CSV

### Batch evaluation
1. Enable **Batch Mode** (topbar)
2. Check multiple studies in the sidebar
3. Configure rubric type and evaluation model
4. Click **⚡ Batch Evaluate**
5. Results appear in each paper's evaluation history

## Design Notes

### LLM-as-judge circularity
The rubric is generated by Claude, but the **evaluatee** is a different LLM (GPT-4o). Claude then grades GPT-4o's answers. Because the generator and grader are both Claude but the evaluatee is separate, this is a valid evaluation design — analogous to an expert writing an exam that a student takes and another expert grades.

Allan's concern about needing a human validator to avoid full circularity is addressed by making the rubric **editable before evaluation** runs. The human reviewer (Tom, Allan, Sabrina, or Malka) can inspect and modify the rubric questions and ideal answers before clicking "Run Evaluation."

### Multi-paper batch design
Batch evaluation generates a fresh rubric per paper (since each paper has unique content), then runs the same evaluation model and grading pipeline in sequence. This enables systematic comparison of LLM performance across a study corpus.
